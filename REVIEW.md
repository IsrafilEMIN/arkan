# Review

What the reviewer must care about in arkan. Keep it short. The reviewer reads it on every pull request; `retro` moves repeated findings into it.

## What failure looks like here

- a skill or playbook: it tells an agent to do something unsafe, or two rules contradict each other.
- docs and tickets: it lies (a claim the code or a cited file does not back).
- ci files: it misroutes a merge (a pr merges without the rule in `docs/seam.md` row 6).
- scripts: it breaks on macos `/bin/bash` 3.2, or it changes files when it says it only checks.

## Skip

- `TODO.md` (generated by `board.sh`).
- `eval/scenarios/` fixtures.
- `docs/agents/review-evals/*/bad.diff` fixtures.

## Review evals

A change to `.github/workflows/arkan-review.yml`, `ci/opencode_agent.py`, `skills/code-review/` or `skills/security-review/` is kept only when `ci/review-eval.sh --compare` misses no case caught before. The script reads the reviewer's prompt, model and turn limit from that workflow, so the rule scores the reviewer ci runs. No ci job runs a model: `scripts/check.sh` runs `--check`, and the person or agent making the change runs `--compare` locally with a headless reviewer. New cases come from `post-merge`; see `docs/agents/review-evals/README.md`.

## Rules

- Give a file and a line as evidence, not a guess from a name.
- At most three nits per review.
- Start the summary with the count of findings, and say plainly when there is nothing to fix.
