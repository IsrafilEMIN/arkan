# Review

What the reviewer must care about in this repo. Keep it short. The reviewer reads it on every pull request; `retro` moves repeated findings into it.

## What failure looks like here

- <one line per kind of failure, for example "docs: it lies", "config: it misroutes">

## Skip

- <paths the reviewer does not review, for example generated files>

## Rules

- Give a file and a line as evidence, not a guess from a name.
- At most three nits per review.
- Start the summary with the count of findings, and say plainly when there is nothing to fix.
